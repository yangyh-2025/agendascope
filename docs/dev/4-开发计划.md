## 〇、团队与工期假定

> **假定**: 团队配置为 **1 名后端工程师（BE）+ 1 名前端工程师（FE）+ 0.5 名 NLP 顾问（NLP，兼职）**。NLP 顾问负责聚类参数调优、LLM prompt 设计与评估集建设，不承担主线编码。若团队配置变化，Phase 2/3 工期需按比例重估。

- **总工时（估算）**: 约 155 人天（BE 115 / FE 28.5 / NLP 11.5），日历周期约 **20 周（100 个工作日，估算）**。前端与后端在 Phase 4 高度并行，NLP 顾问在 Phase 2/3/5 穿插投入。
- **任务编号**: T{Phase}.{序号}；负责列 BE/FE/NLP 对应上述角色。
- **模块归属**: collector（采集）、extractor（抽取）、nlp_pipeline（NLP 管线）、agenda_engine（议程引擎：聚类/溯源/纠错）、llm_service（LLM 推理）、api_server（API+业务）、frontend（前端）、alerting（预警）。模块边界与接口定义见 `1-技术方案.md` 第四章。
- **验收口径**: 所有标注"（估算）"的指标为 PRD 中的估算目标，验收时以 PRD 第六/八章为准。

### 2.2 议程识别准确率回放测试（核心专项）

> 这是本平台区别于普通舆情系统的验收核心。测试集（T5.1）为 ≥20 个已知议程设置历史案例（估算），含"新疆棉"类事件与多语言报道对；回放方式：按原始发布时间顺序重放文章流，模拟"首日零星报道 → 次日多国跟进"的真实节奏。

| 指标 | 目标（估算） | 测量方法 | 不达标处置 |
|------|-------------|---------|-----------|
| 首发源判定准确率 | ≥85%（严于 PRD 底线 80%） | 回放案例的首发国/首发源与标注比对 | 复盘判定逻辑与时间锚点可信度规则，调整后全量重跑 |
| 次日归并正确率 | ≥90% | 次日应归并的议题对是否复用 topic_id；不应归并的是否被误并 | 调 0.85 归并阈值（估算）与 Agglomerative 参数；误并对入"不可归并"名单回归 |
| 议题误并/误拆率 | ≤5% | 回放全程人工抽检 + 拆分回滚/再合并操作统计 | 触发 D-007 重评估：冻结自动归并改人工确认模式 |
| 事件误报率 | ≤20% | 回放产出事件与标注事件比对（多国独立自发报道应判不成立） | 复盘判定条件 a–d 与终审审查官 prompt |
| 跨语言同事件归并率 | ≥70% | 已知同事件中/英/阿语报道对归入同一议题比例 | 评估向量模型，预留 LaBSE 切换接口（ADR-005 后续动作） |
| 全链路延迟 | P95 ≤30 min，红线 ≤2 h | 压测中 pipeline_latency_sample 分桶统计 | 按 `1-技术方案.md` 延迟预算分解表逐段定位 |

回放测试纳入 CI  nightly 任务（单机资源允许时）：每次聚类参数/归并阈值/prompt 版本变更必须重放全量案例集，指标回退即阻塞合并。

### 2.3 降级演练清单（对应 PRD 8.5）

- [ ] LLM 不可用 → c-TF-IDF 兜底 + `naming_method` 标记 + P1 告警 + 恢复后回填
- [ ] BERTopic 不可用 → 关键词匹配聚类 + `cluster_method` 标记 + 恢复后重聚类回填
- [ ] GDELT 连续 1h 无响应 → 读本地缓冲，核心 70% 覆盖国家不受影响
- [ ] NLP worker 积压 >10,000 持续 10 min → "先入库后聚类"，可见性红线优先
- [ ] 正文抽取失败 → readability 降级 → 仅摘要入管线 `content_status=partial`
- [ ] LLM 终审不可用 → 事件直进人工复核队列，不自动告警
- [ ] 统计检验超时 >5 min → 保留上版结果，连续 3 次失败告警

## 三、自测清单（开发提交前自查）

### 功能正确性
- [ ] Happy Path 正常流程测试通过
- [ ] 异常流程（参数错误/权限不足/资源不存在）返回正确错误码（错误码表见 `2-详细设计.md`）
- [ ] 边界条件（空列表/最大值/并发/单源爆发 >500 篇/小时）处理正确
- [ ] 数据库事务回滚正确；队列消费失败进重试/DLQ 不丢消息

### 平台特定正确性
- [ ] 时间统一 UTC 存储，无发布时间文章 `time_source=crawled` 且不参与高置信首发判定
- [ ] 转载合并保留全部来源（related_docs），不丢来源列表
- [ ] 每次自动修正（归并/首发改判/置信度变化）写入 revision_log 且含修正前后值 + 触发证据 + 模型/prompt 版本
- [ ] 人工否决的判定不会被后续自动修正推翻
- [ ] 降级发生时有字段标记（`naming_method`/`cluster_method`/`detection_method`）且上报告警——**绝不静默降级**
- [ ] 统计检验在样本 <100 篇时拒绝输出结论

### 代码质量
- [ ] 无 print / 调试代码残留；硬编码配置已提取到配置模块
- [ ] 关键逻辑有单元测试，核心算法覆盖率 ≥85%
- [ ] 无明显 N+1 查询；慢查询有索引（EXPLAIN 验证）
- [ ] 密码/Token/密钥无硬编码、不打印日志
- [ ] trace_id 在新增链路节点中正确传递

### API 契约
- [ ] 请求参数校验完备；响应结构符合 `{code, data, message}` 与 `2-详细设计.md` 定义
- [ ] 错误信息不暴露内部实现；敏感字段已脱敏
- [ ] 文章接口不输出正文全文（仅标题 + ≤150 字摘录 + 原文链接，版权合规 L1）

### 数据库
- [ ] Migration 有对应回滚 SQL；新增列有 DEFAULT 值
- [ ] 表名/字段与 `2-详细设计.md` DDL 一致（snake_case）

### 性能与合规
- [ ] 外部调用（GDELT/Webhook/LLM）有超时设置
- [ ] Webhook URL 经白名单校验（防 SSRF）
- [ ] 新增依赖许可证已核查（无 GPL/AGPL 链入自有代码；传染性组件仅独立容器集成）
