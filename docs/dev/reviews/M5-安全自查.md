### 1.3 处置建议

**高危（需排期整改）：**

- **transformers 4.57.6 → ≥5.5.0**：含 1 条严重 RCE（CVE-2026-4372）。当前项目仅以 `from_pretrained(本地目录)` 离线加载 Qwen2.5-0.5B-Instruct（`backend/app/llm/engine.py:68-69`），模型目录经 compose 只读挂载（`deploy/docker-compose.yml:165-167` `:ro`），不加载任何不可信 checkpoint/config，现实暴露面较低；但 5.x 为大版本升级，需对命名管线（naming-worker）做回归验证后排期升级。升级前临时缓解：保持 `models/` 目录只读、禁止从 Hub 在线拉取、定期校验模型文件哈希。
- **ecdsa 0.19.2（CVE-2024-23342）**：无修复版本。ecdsa 为 python-jose 的传递依赖，本项目 JWT 仅用 HS256（`backend/app/config.py:35` `jwt_algorithm="HS256"`），签名实际走 cryptography 后端，ecdsa 不在签名路径上，风险低；建议持续跟踪上游，或将 python-jose 替换为 PyJWT 以彻底移除该依赖。

**中低危：** 无其他条目。FastAPI/uvicorn/sqlalchemy/redis/pydantic 等核心依赖当前版本均无已知漏洞。

## 5 结论与整改优先级

**总体结论：** 代码层安全基线良好（无高危代码漏洞、身份鉴别与 RBAC 机制完整、启动弱配置防护到位）；主要差距集中在**部署传输层（全明文、数据存储无认证且端口外暴露）**与**双因素鉴别缺失**，另有 transformers 依赖含严重 RCE 漏洞需排期升级。

**P0（上线前必须完成）：**

1. 传输加密与网络隔离：nginx 反代终结 TLS；PG/Redis/ES 端口不再映射宿主机；ES 开启 xpack security 或网络层隔离（等保不符合项，§3）
2. transformers 升级 ≥5.5.0（CVE-2026-4372 严重 RCE），升级前保持模型目录只读 + 禁在线拉取作为缓解（§1）
3. 生产部署模板：补齐生产 compose，杜绝 dev 弱默认值编排直接交付（`config.py:78-98` 防护只在非 dev 生效）

**P1（上线后 1 个迭代内）：**

4. TOTP 双因素落地（字段已预留，`models/user.py:25`）（等保不符合项）
5. 审计补盲：角色变更（`system_admin.py:72-79`）与审计导出（`api/routes/audit.py:115-137`）写入 audit_logs；明确审计留存 ≥6 个月并纳入加密备份
6. 备份加密默认开启（backup.sh AES-256 当前为可选）

**P2（持续改进）：**

7. access token 有效期 120min 缩短至 ≤30min；内部 token 比较改 `hmac.compare_digest`
8. `llm/engine.py:68-69` 加 `local_files_only=True`；关键 assert 改显式异常（bandit B615/B101）
9. 许可证收尾：redis 固定 7.2-alpine；lid.176/Qwen 补附 LICENSE 文件；llvmlite 许可证人工标注 BSD-2-Clause；ecdsa 持续跟踪或替换 PyJWT
