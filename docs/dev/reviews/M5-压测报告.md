## 1. 指标口径

- 加压强度：按 ~2.2 万篇/天（估算）回放加压，常态 15 篇/分钟；峰值 100 篇/分钟周期性突发。
- 考核指标：端到端「新闻发布 → 平台可见」**P95 ≤ 30 min 为 PASS，红线 ≤ 2 h**（超红线样本数单列）。
- 全量记录：Redis 队列积压（`raw:articles` XLEN + 各消费组 pending）、LLM 耗时（`llm_judgements.latency_ms` 分 task_type 统计）、快照刷新（`agenda_snapshots` 窗口内落表量；刷新耗时无独立埋点，报告如实注明）。
- 延迟数据源：`pipeline_latency_sample` 表（`backend/app/nlp/latency.py`），字段 `article_id / channel / country_code / published_at / visible_at / latency_ms / latency_bucket / sampled_at`，分桶 `<5m / 5-15m / 15-30m / 30-60m / 1-2h / >2h`。P50/P95/P99 用 `percentile_cont` 计算，与 `latency.py` 的 `channel_stats` 口径一致。
- 已知口径限制：该表只覆盖 `published_at → visible_at` 端到端延迟，**无采集→向量化→归簇→可见的逐环节分段字段**；分段瓶颈以队列积压趋势 + LLM 耗时 + 快照落表时间佐证，FAIL 时按 `1-技术方案.md` 延迟预算分解表逐段定位。

## 2. 注入入口（读代码确认的真实链路）

1. 注入走**内部采集 API**：`POST {COLLECT_API_BASE}/internal/collect`（`backend/app/api/routes/internal.py`），Bearer 认证 `COLLECTOR_INTERNAL_TOKEN`。
2. 载荷为 `app.schemas.collect.CollectedPayload`（`uuid / source_id / adapter_type / url / title / content / informant / pub_time / time_source` 等）。
3. `CollectService.ingest`（`backend/app/services/collect_service.py`）幂等去重后落 `articles` 表（写入即设 `visible_at`，可见性优先），并 `XADD` Redis Stream **`raw:articles`**（`app.db.queue.STREAM_RAW_ARTICLES`），后续向量化/归簇由消费该 Stream 的 worker 异步完成。
4. 脚本自动在 `sources` 表创建幂等合成源「STRESS-TEST 合成源」，注入文章 url/title 携带唯一 marker（`stress-<时间戳>` 或 `--marker` 指定），采样时按 `articles.url LIKE %marker%` 关联 `pipeline_latency_sample` 只统计本次压测文章。

## 3. 脚本用法

```bash
# 加压 + 采样 + 出报告（退出码：PASS=0 / FAIL=2 / 环境不可达=1）
.venv/Scripts/python scripts/stress_test.py run \
    --rate-per-min 15 --peak-per-min 100 --peak-every-min 5 \
    --duration-min 30 --settle-min 10 \
    --out docs/dev/reviews/M5-压测报告.md

# 仅基于已有 pipeline_latency_sample 数据出统计
.venv/Scripts/python scripts/stress_test.py report [--marker stress-xxx] [--since-hours 24]
```

环境变量：`DATABASE_URL`（默认 `postgresql+psycopg2://agenda:agenda_dev_pwd@localhost:5432/agendascope`）、`REDIS_STREAM_URL`/`REDIS_URL`（默认 `redis://localhost:6379/1`）、`COLLECT_API_BASE`（默认 `http://localhost:8000`）、`COLLECTOR_INTERNAL_TOKEN`（`run` 必填，与服务端一致）。

## 5. 完整环境下的执行步骤与达标判定

前置：`deploy/docker-compose.yml` 起 PostgreSQL(5432)/Redis(6379)，alembic 迁移到 head，后端 API 运行于 8000 端口，NLP/聚类 worker 正常消费 `raw:articles`。

1. 设置环境变量（与 `.env` 一致）：`DATABASE_URL`、`REDIS_STREAM_URL`、`COLLECTOR_INTERNAL_TOKEN`。
2. 执行 `scripts/stress_test.py run`（默认 30 min 加压 + 10 min 消化）。
3. 脚本自动完成：创建合成源 → 按 15/min 常态 + 每 5 min 一次 100/min 峰值注入 → 每分钟记录队列积压 → 消化期轮询至队列清空 → 统计 P50/P95/P99/max、分桶、分通道、LLM 耗时、快照落表 → 覆盖写本报告。
4. 判定标准：
   - **PASS（退出码 0）**：端到端 P95 ≤ 30 min 且无超 2 h 红线样本；
   - **FAIL（退出码 2）**：P95 > 30 min 或存在超红线样本，报告附分桶分布、分通道 P95、队列积压曲线、LLM 耗时等瓶颈明细，按延迟预算分解表逐段定位后调权重跑。
