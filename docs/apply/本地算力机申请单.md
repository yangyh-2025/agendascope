## 一、申请事由

AgendaScope 是我主导开发的**全球议程设置监控平台**，目前已在阿里云 2核2G/3Mbps 服务器（wordread.cn）稳定运行，每日采集 172 国 408 个媒体源的 ~500 篇新闻，支撑议题聚类、实体识别、关系抽取、议程事件检测等核心功能。

当前痛点：**云端 2 核 2G 算力严重不足**——
- BERTopic 聚类算法曾因内存不足被关闭，只能用简化版 Agglomerative
- 数据库 + API + 前端 + 所有 worker 挤在一台小机器上，OOM 频发（已修复 85+ 次崩溃）
- 3Mbps 带宽成为采集瓶颈（408 个源走代理）
- 无法在云端运行更大的 embedding 模型或更复杂的算法

**解决方案**：把计算从云端搬到本地。云端只保留 PostgreSQL + 后端 API + 前端 nginx（3 个服务），本地算力机做所有采集/NLP/聚类/关系抽取/LLM 调用，通过公网 PG 连接读写数据库。

## 三、性能预估

| 任务 | 当前云端（2C2G） | 本地算力机（8C32G） | 提升 |
|------|----------------|-------------------|------|
| 采集吞吐 | ~50 篇/小时（3Mbps 瓶颈） | ~500 篇/小时（100Mbps） | 10x |
| NLP embedding | 2 篇/秒（CPU 2 核） | 10 篇/秒（CPU 8 核） | 5x |
| BERTopic 全局聚类 | **跑不动**（OOM） | 3 分钟/轮（32GB） | 启用 |
| 关系抽取 LLM 调用 | 受 2 核限制（云 API QPS 2） | 云 API 全速（QPS 10） | 5x |
| 快照聚合 | 30 分钟/轮 | 5 分钟/轮 | 6x |
| **发布到可见时延** | ~30 分钟 | **≤15 分钟** | 2x |

## 四、网络与安全

- **网络需求**：100Mbps 带宽 + 能访问境外（采集 408 个媒体源，多在国外）
- **代理需求**：本地运行 mihomo/Clash 代理（已有经验，阿里云同款）
- **数据库连接**：公网 PostgreSQL 连接云端 39.106.2.28:5432，**强制 SSL 加密**
- **账号隔离**：本地 worker 用专用 `agendascope_write` 账号（DML 权限），云端保留只读账号 `agendascope_read`
- **防火墙**：云端宝塔面板配 IP 白名单，只放行实验室公网 IP 段
- **数据安全**：所有写操作走 SQL 事务，失败可重试不丢；本地不存原始数据（写完即弃）
