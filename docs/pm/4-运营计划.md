### 3. 技术风险

| 风险 | 描述 | 概率 | 影响 | 缓解策略 | 触发信号 |
|------|------|------|------|---------|---------|
| T1 媒体源失效/反爬 | 57 国、每国多家主流媒体的 RSS/网页源会周期性失效（改版、feed 下线、反爬、GDPR cookie 墙）；调研报告 1 指出部分站点不提供全文 feed 或根本不提供 RSS，需 RSSHub 补洞 | 高 | 高 | ① 三级采集降级链：RSS 高频轮询（重点源 1–5 分钟）→ RSSHub 补源 → GDELT（15 分钟更新、100+ 语言）兜底；② 源健康度自动巡检（每日全量 + 每小时重点源），失效自动告警；③ trafilatura 抽取失败降级 readability-lxml（逐级降级策略，来源：<https://www.justtothepoint.com/code/scrape/>）；④ 每国源数留出冗余（目标覆盖 70% 受众，按 85% 配置余量）（估算） | 单国有效源覆盖率跌破 70%；单源连续 24h 无新文章；正文抽取成功率 < 90%（估算） |
| T2 多语言 NLP 质量不达标 | 跨语言话题聚类依赖 fastText lid.176（官方仓库已归档，来源：<https://github.com/facebookresearch/fastText>）+ 云端 bge-m3 跨语言向量（1024 维，SiliconFlow API）+ BERTopic 增量聚类；低资源语言（如斯瓦希里语、阿姆哈拉语）向量质量差会导致议题聚类混乱，直接动摇"跨国对比"核心卖点 | 低 | 高 | ① MVP 上线前做逐国抽样人工评估（每国抽 200 条，话题一致性人工标注）（估算）；② 低置信语言自动隔离为独立话题空间并标注"低置信"；③ 降级链：LLM 不可用时议题标签降级为 BERTopic c-TF-IDF 关键词标签；聚类不可用时降级为关键词匹配 + fastText 语种分组（PRD 第八章降级方案）；④ 保留换 LaBSE 向量模型的接口 | 人工评估话题一致率 < 80%（估算）；某语种文章聚类后"其他/杂项"类占比 > 30%（估算） |
| T3 GDELT 依赖 | GDELT 是覆盖广度与兜底延迟的关键（15 分钟更新、免费、100+ 语言，来源：<https://www.gdeltproject.org/>）；其为公益项目，存在服务变更、限流、甚至停供的可能；Python 客户端 gdelt-doc-api 维护放缓（最后更新 2025-04，225★） | 高 | 高 | ① 直接封装 GDELT DOC 2.0 REST API（免费无需 key），不依赖第三方客户端；② GDELT 只作兜底与广度补充，核心 70% 覆盖媒体以自采 RSS 为第一来源，GDELT 中断时平台核心国家监控不受影响；③ 每日下载 15 分钟批 CSV 做本地缓冲，API 故障时降级读缓冲；④ 关注 GDELT 官方博客公告 | GDELT API 连续 1h 无响应；DOC 2.0 API 检索窗口（约 3 个月）收窄 |
| T4 各国媒体覆盖率数据不可靠 | "每国主流媒体合计受众覆盖率 ≥70%"是产品核心口径，但调研报告 1 明确指出：一国"主流媒体"无公认定义，商业平台（Factiva 3.3 万源、Aylien 9 万源、Event Registry 15 万源）均不公开逐国覆盖统计，精确覆盖率只能用目录数据估算 | 高 | 中 | ① 按既定操作化口径：维基百科各国报纸列表 + ABYZ News Links + Media Cloud Directory + awesome-rss-feeds + Similarweb 流量排名取交集；② 逐国标注覆盖率估算置信度（高/中/低三档）并在前端明示；③ 每季度复核一次媒体清单，纳入新崛起媒体 | 某国置信度连续两季为"低"；用户质疑某国遗漏头部媒体 |
| T5 单机服务器故障 | 产品为 Docker Compose 单机部署（私有化唯一形态，见 D-005），无集群冗余，硬件故障/断电即全停 | 高 | 低 | ① 每日全量 + 增量备份（保留 30 天），RTO ≤ 30 分钟、RPO ≤ 5 分钟（与 PRD 非功能需求一致）；② Docker Compose 配置全量版本化，恢复 = 新机器一键重建 + 数据回放；③ 部署脚本内置健康自检与 systemd/Docker restart=always | 可用性跌破 99.5%；备份任务失败未被发现 |
| T6 云端 LLM API 可用性/配额限制 | 议题分类、命名、归并、摘要与议程溯源首发表述判定全部调用云端 LLM API（讯飞星辰 MaaS，见 D-006），并受 QPS 2 / 并发 2 配额限制（估算）；API 服务不可用、配额耗尽或出网通道中断时，议题管线与首发判定将停摆或延迟，低资源语言的议题命名/归并质量也可能不达标 | 高 | 高 | ① 限流信号量：LLM_MAX_CONCURRENCY=2 线程信号量对齐配额，超限请求排队不堆积；② 管线异步化：LLM 调用走离线批处理队列，不阻塞采集与告警主链路；③ 完整降级链：LLM 不可用 → BERTopic c-TF-IDF 关键词标签兜底（naming_method=ctfidf_fallback 标记 + P1 告警）；聚类不可用 → 关键词匹配兜底（PRD 第八章）；④ 恢复回填：API 恢复后对降级时段议题自动回填 LLM 命名/判定并留痕；⑤ 每类 LLM 任务建评估集，上线前跑 baseline 验收 | 议题标注 P95 时延 > 10 分钟（估算）；LLM 议题命名/归并人工抽检合格率 < 85%（估算） |
| T7 自我纠错误并/误拆导致议题图谱污染 | US-16 引入议题生命周期状态机与次日自动归并（相似度 ≥0.85 估算即并入旧议题、topic_id 复用）、增量重估自动修正首发判定；一旦阈值失当或向量质量差（尤其低资源语言，与 T2 联动），自动归并会把不同议题误并、把同一议题误拆，错误随 topic_id 复用持续累积，污染议题图谱与议程溯源结论；IIS 的合并回写本身即为半成品（writeback 是 TODO），自行落地存在实现风险 | 高 | 高 | ① 人工校正优先级高于机器：分析师可人工确认/否决任何自动修正，否决结果不再被机器覆盖；② 修正历史（revision_log）全程留痕（修正前/后值、触发证据、模型与 prompt 版本），误并可一键回滚；③ 监控看板新增"议题误并/误拆率"指标（估算），纳入每周站会复盘；④ 双阈值 + 每小时全局重聚类校正（估算）抑制误差累积；⑤ 归并/拆分操作先写 revision_log 再生效，低置信修正先进入"疑似"状态等待确认 | 议题误并/误拆率 > 5%（估算）；分析师人工否决率 > 20%（估算）；同一议题 7 天内被自动修正 ≥3 次（估算） |

### 7. 最重要的 5 个风险

1. **T1 媒体源失效/反爬（概率高 × 影响高）**：这是 7×24 实时体系的"慢性失血点"——任何一个重点国家的头部媒体源失效，直接跌破"每国覆盖率 ≥70%"的核心承诺，P95 ≤30 分钟、红线 ≤2 小时的延迟指标也随之失守。应对主线是"三级降级链 + 自动巡检 + 覆盖冗余"（见 T1），并将源健康度做成管理员可见的看板，把隐性风险显性化。
2. **L1 新闻版权（概率高 × 影响高）**：私有化部署+全文采集的组合在多国法域下没有一劳永逸的答案。一旦收到主流媒体集团的下架要求，可能被迫整源下线，覆盖率与产品信誉双损。底线设计是"全文不出库"（分析可用、展示用摘录+链接），把侵权面压缩到 TDM 分析豁免的范围内。
3. **T3 GDELT 依赖（概率高 × 影响高）**：GDELT 免费提供全球 100+ 语言广度，但它是公益项目，无 SLA。缓解的核心是架构定位——GDELT 只做"兜底+广度补充"，核心 70% 覆盖媒体永远以自采 RSS 为第一来源；GDELT 全停时平台降级而非瘫痪。
4. **L4 保密/安全合规审查不通过（概率高 × 影响高）**：面向国家安全机关与涉密科研机构的交付形态下，保密审查是"一票否决"项，审查不通过意味着整个商业模式不成立。应对主线是把合规做进架构而非事后补救：私有化部署 + 云 API 经批准出网通道、组件来源清单化、支持全盘代码审计与断网验收、操作与导出全量留痕（见 L4）。
5. **T6 云端 LLM API 可用性/配额限制（概率高 × 影响高）**：议程溯源（US-06）是产品的差异化核心，其议题命名/归并/首发判定质量依赖云端 LLM API（讯飞星辰 MaaS，D-006）。应对主线是"限流信号量 + 完整降级链（LLM → c-TF-IDF → 关键词匹配）+ 恢复回填"，确保 LLM 不可用时平台降级而非瘫痪。

| **备选方案** | 1. 纯传统 NLP（BERTopic c-TF-IDF + 规则）——无 LLM 依赖，但议题可读性与首发判定质量差，保留为降级兜底；2. 本地部署开源 LLM（如 Qwen 系列）——无外部依赖但需 GPU 硬件、分发权重、推理质量与运维成本高，降级为"极端降级"选项，默认不启用；3. 自训小模型逐任务建模——工程量最大，放弃 |
| **影响** | 技术：新增 T6 风险（云端 LLM API 可用性/配额限制）；工程：议题管线简化为"聚类 + LLM 标注"，US-04 强化与 US-06 议程溯源、US-15 人物首发监测均由其支撑；合规：云 API 调用不分发本地权重，出网通道纳入 L4 保密审查；产品：议程设置事件自动判定成为差异化核心 |
| **可逆性** | 可逆（成本：中）——降级链保留：LLM 不可用 → BERTopic c-TF-IDF 关键词标签兜底（naming_method=ctfidf_fallback + P1 告警 + 恢复回填）；聚类不可用 → 关键词匹配兜底 |
| **重评估触发器** | 议题标注 P95 时延 > 10 分钟（估算）；LLM 命名/归并人工抽检合格率 < 85%（估算）；云端 LLM API 配额/可用性长期无法满足生产（QPS 2 / 并发 2 显著不足），需评估扩容或极端降级方案 |

### D-007: 引入议题生命周期管理与增量重估自我纠错机制（2026-07-24 v1.2 新增）

| 字段 | 内容 |
|------|------|
| **日期** | 2026-07-24 |
| **决策者** | 产品 + 技术负责人 |
| **决策** | 平台引入议题生命周期管理与增量重估自我纠错机制（US-16，P0）：① 议题生命周期状态机：萌芽（孤证微簇，size=1 微簇不丢弃）→ 形成中 → 已确认 → 演化（合并/分裂）→ 消亡（连续 N 天无新报道自动归档，N=7 估算）；② 次日自动归并：新议题先与历史议题做跨语言向量比对，相似（≥0.85 估算）则并入旧议题（topic_id 复用），否则开新议题；③ 增量重估与判定修正：新证据（更早报道、新来源）出现时自动重跑首发源判定，判定变化自动更新并写入修正历史（revision_log），AgendaEvent 置信度随证据自动升级（观察中→疑似→确认）或撤销；④ 全程留痕可审计，人工校正优先级高于机器 |
| **背景** | 实时监测舆情、实时分析议程的业务需求下，当前识别的议程可能不对（首发源误判、议题误并/误拆），或一个新议程首日仅有零星报道尚未形成、次日才成形——系统必须随证据积累自动更新与修正，否则议题图谱错误会持续累积、议程溯源结论失真。借鉴开源项目 IntelligenceIntegrationSystem（Apache-2.0，380★，<https://github.com/SleepySoft/IntelligenceIntegrationSystem>）的主题档案合并（topic_id 复用）、回声消除（同日相似度 ≥0.65 或 3 日内 ≥0.85 折叠为同一议题节点并保留全部来源列表）与在线增量聚类双阈值（T_event=0.85 / T_dup=0.95，估算）设计；其合并/分裂回写为半成品（writeback 是 TODO），本平台需自行落地并超越——增加分裂与消亡机制（对应 PRD Epic 2 / US-16 与第八章聚类策略升级） |
| **备选方案** | 1. 人工定期整理议题与修正判定——质量最高但不可扩展：57 国数百源日增数千条报道，人工整理周期以周计，无法支撑"实时监测、次日成形"的业务节奏，被否；2. 纯在线增量聚类、无全局校正与生命周期管理——增量归簇误差随时间累积，议题只增不减、只合不分，图谱逐渐失真（IIS 即止步于此），被否 |
| **影响** | 产品：新增 US-16（P0，Epic 2）——US-06 管"识别一次议程设置"，US-16 管"识别结果的持续演化与纠错"，二者边界清晰；技术：Topic 表新增 lifecycle_state/confidence/merged_into/last_seen_at 字段，AgendaEvent 表新增 confidence/status/revision_log 字段；聚类策略增加 Agglomerative 硬距离阈值聚类（cosine 阈值 0.25，average linkage，估算）+ 每小时全局重聚类校正（估算）；风险：新增 T7（自我纠错误并/误拆导致议题图谱污染），以"人工否决优先 + 修正留痕可回滚 + 误并率监控"缓解 |
| **可逆性** | 可逆（成本：中）——生命周期状态机与 revision_log 为叠加层，关闭自我纠错后退回"仅识别、不演化"模式，已写入的修正历史不回删 |
| **重评估触发器** | 议题误并/误拆率 > 5%（估算）；分析师人工否决率 > 20%（估算）；次日归并正确率在验证集上 < 90%（估算） |
