# AgendaScope 观澜（全球议程设置监控平台）— 产品全景

---

## 第一部分：愿景与战略

### 1. 愿景声明 (Vision Statement)

让国家安全机关与国际关系/国际政治/国家安全研究机构中每一位没有编程基础的业务专家，都能像看天气预报一样，实时看清全球舆情动向，并第一时间识别出"谁在为世界设置议程"。

### 2. 使命 (Mission)

AgendaScope 观澜是一个私有化部署在用户自有服务器/内网中的全球议程设置监控平台。它以议程设置理论三层框架（客体显著性 → 属性议程设置 → 网络议程设置 NAS）为分析内核，实时监控约 30 个主要经济体及全球南方代表性经济体中"合计受众覆盖率 ≥70%"的主流新闻媒体，在新闻发布后 2 小时红线内（P95 ≤ 30 分钟）将各国媒体议程转化为可交互的地图、时间线与议题网络图；并在此之上识别"议程设置"行为——当某国（媒体、官员、重要人士、智库、国际组织）率先提出一个议题、随后多国媒体跟随报道时，平台自动识别首发源、跟随国序列与时间差，呈现完整传播链路证据链，判定为议程设置事件并告警，让零编程基础的业务专家完成以往需要数据团队才能完成的计算传播分析与舆情研判。

为什么重要：议程设置是传播学最稳健的发现之一（1968 年 Chapel Hill 研究中媒体议程与公众议程的 Spearman 相关系数高达约 0.97，见 [McCombs & Shaw 1972 参考文献页](https://www.jmir.org/2022/4/e34321/)），而识别"谁在设置议程、为谁设置、以多快速度扩散"正是国家安全舆情研判与国际关系研究的核心问题。但今天想要回答这个问题的人，要么支付 $10,000+/年的商业舆情平台（且数据托管在厂商云端，安全场景不可用），要么自己写爬虫和模型。观澜把这条路压缩到"一次内网 Docker Compose 部署 + 10 分钟配置看板"。

### 3. 北极星指标 (North Star Metric)

- **指标名称**: 每周活跃「国家×议题」监测会话数（WAS, Weekly Active country-issue monitoring Sessions）——用户在一周内至少完成一次"选定国家 + 选定议题"的看板查看/分析会话即计为 1 个
- **当前基线**: N/A — 新产品
- **6 个月目标**: 500/周（估算）
- **12 个月目标**: 2000/周（估算）

辅助健康指标：每国媒体覆盖率 ≥70%；系统可用性 99.5%；新闻发布 → 平台可见 P95 ≤ 30 分钟（红线 ≤ 2 小时）；零编程业务用户核心任务 ≤3 步完成、首次看板配置 ≤10 分钟；议程设置事件识别准确率 ≥80%（估算目标，验证方法见第 8 节）。

### 4. 核心问题

#### 4.1 问题描述

国家安全机关的舆情分析师与国际关系/国家安全研究机构的研究者需要回答的不只是"此刻全球主流媒体在报道什么"，更是"**这个议题是谁先提出来的、哪些国家的媒体在跟随、这是一次自然传播还是一次有组织的议程设置**"。典型案例：美国官员/媒体率先提出"新疆棉"议题 → 多国媒体在短时间内跟随报道 → 涉华负面议程在国际舆论场扩散。业务专家需要在第一时间识别首发源（国家/媒体/人物）、跟随报道的国家序列与时间差，并拿到完整证据链支撑研判与上报。但现有路径全部存在硬门槛：商业平台（Meltwater 约 $15,000/年起、Brandwatch 年合同约 $10,000–15,000 起、Talkwalker 中位约 $27,000/年）价格高企、以社媒聆听为主、不提供议程设置理论层面的测量，且为纯 SaaS 形态——数据托管在厂商云端，安全保密场景根本无法使用（来源见第四部分）；免费的 GDELT 和 Media Cloud 只提供原始数据与检索接口，需要 SQL/编程能力才能分析；开源舆情项目（TrendRadar 60.9k★、BettaFish 41.8k★）面向中文热搜与技术用户，既无全球媒体覆盖口径，也无理论化的显著性测量；国内政务舆情厂商（蚁坊、清博等）以国内舆情为主，缺乏全球主流媒体覆盖与议程溯源能力。结果是：最需要议程溯源能力的一群人（国安舆情分析师、国际关系研究者）反而在用 Excel + 人工采样做跨国议程研判。

#### 4.2 现有解决方案及其不足

| 现有方案 | 不足 |
|----------|------|
| 商业舆情平台（Meltwater / Brandwatch / Talkwalker） | $10k–50k/年报价制；社媒优先，传统媒体监测为辅；无议程设置三层分析（无 NAS、无 intermedia agenda setting）、无议程溯源；纯 SaaS，数据托管在厂商云端，安全保密场景不可用 |
| 免费数据库（GDELT / Media Cloud） | 只有数据与 API，无面向业务专家的分析产品；GDELT 自动抽取存在转写/翻译/实体识别误差（官方与学界均提示），需用户自行清洗建模 |
| 开源舆情项目（TrendRadar / BettaFish） | 面向中文热搜与社媒平台，非全球主流媒体；需要命令行/Docker 操作能力，目标用户实为开发者 |
| 国内政务舆情厂商（蚁坊鹰眼速读网 / 清博 / 识微） | 以国内全网舆情为主，海外媒体覆盖弱；无议程设置理论分析框架与跨国议程溯源能力；报价制 |
| 自建爬虫 + 学术工具链 | 需要编程能力；媒体源清单、覆盖率口径、多语言 NLP 管线均需自行搭建，单人维护成本极高 |

### 5. 价值主张

**一句话**: 私有化部署的全球舆情与议程设置行为监控平台——输入零代码，输出论文级的议程设置三层分析与跨国议程溯源证据链。

**核心差异化**:
1. **议程设置行为识别与议程溯源（差异化核心，US-06）**: 市面唯一能自动识别"这是一次议程设置"的产品——识别议题首发源（国家/媒体/人物）、跟随报道的国家序列与时间差、传播链路图，自动判定议程设置事件并告警，呈现完整证据链。底层测量方法为议程设置理论完整测量链：第一层客体显著性、第二层属性议程设置（实质属性 + 情感属性）、第三层网络议程设置（NAS，议题-属性关联网络的显著性转移，Guo & McCombs），配套时滞互相关、Granger 因果检验、QAP/MRQAP 网络相关分析与媒体间议程设置（intermedia agenda setting）——这正是 Guo & Vargo (2017) 等计算传播研究的工业化落地。
2. **自我纠错的议程演化追踪（US-16，P0）**: 与 US-06 边界清晰——US-06 管"识别一次议程设置"，US-16 管"识别结果的持续演化与纠错"。议题生命周期状态机：萌芽（孤证微簇）→ 形成中 → 已确认 → 演化（合并/分裂）→ 消亡（连续 N 天无新报道自动归档，N=7 估算）；次日自动归并——新议题先与历史议题做跨语言向量比对，相似（≥0.85 估算）则并入旧议题（topic_id 复用），否则开新议题，解决"今天只有零星报道、明天才成形"的议程滞后问题；增量重估与判定修正——新证据（更早报道、新来源）出现时自动重跑首发源判定，判定变化时自动更新并写入修正历史（revision_log），前端标注"该判定已于 X 时修正"，AgendaEvent 置信度随证据自动升级（观察中→疑似→确认）或撤销；全程留痕——每次自动修正记录修正前/后值、触发证据、模型与 prompt 版本，分析师可人工确认/否决（人工校正优先级高于机器）。参考开源项目 IntelligenceIntegrationSystem（Apache-2.0）的主题档案合并（topic_id 复用）与在线增量聚类设计，其合并/分裂回写未完成，本平台自行落地并超越（增加分裂与消亡机制）。
3. **70% 覆盖率口径**: 每国主流媒体不是"随手选几家"，而是按"维基百科各国报纸列表 + ABYZ News Links + Media Cloud Directory + awesome-rss-feeds 清单 + Similarweb 流量排名取交集"操作化为合计受众覆盖率 ≥70%，逐国标注覆盖率估算置信度——这是学术上可辩护、业务上可审计的独家口径。
4. **本地化 LLM 智能（决策 D-006）**: 议题分类、命名、归并、摘要、首发表述判定等 NLP 环节优先调用大模型以简化工程；安全场景硬约束下 LLM 必须本地化部署（开源模型本地推理，如 Qwen 系列，估算硬件 1×24GB 显存 GPU 或 CPU 量化推理）或使用经机构批准的 API，数据不出用户服务器/内网；LLM 不可用时降级为 BERTopic c-TF-IDF 关键词标签，聚类不可用时降级为关键词匹配。
5. **零编程可用性与安全合规交付**: 核心任务 ≤3 步、首次看板配置 ≤10 分钟、Docker Compose 一键私有化部署；支持完全离线内网部署（含 LLM 本地推理、离线地图瓦片或内网地图服务、无外部依赖的安装包），满足数据不出域、7×24 运行的硬要求。竞品要么贵且是 SaaS（商业平台），要么难（GDELT/开源），观澜是唯一"既不需要技术基础、又能进内网"的全球议程溯源工具。

### 6. 战略支柱

1. **理论即产品** — 把议程设置三层框架与议程溯源方法从论文方法（QAP/MRQAP、Granger 因果、时滞互相关）封装为默认分析视图与自动判定流程，建立"学术方法 → 产品功能"的一一映射，形成竞品短期无法复制的方法论壁垒。
2. **覆盖即信用** — 以逐国 ≥70% 受众覆盖率口径（含置信度标注）作为数据质量承诺，将"主流"从模糊概念变为可审计清单，成为机构采购与研究引用的信任基础。
3. **私有化即合规** — 私有化部署是唯一交付形态（无 SaaS 形态）：单机 Docker Compose 常驻部署 + 全离线 NLP/翻译栈（argos-translate / LibreTranslate）+ 本地化部署 LLM；必须支持完全离线内网部署（离线地图瓦片或内网地图服务、无外部依赖的安装包），对标网络安全等级保护（等保 2.0 三级，估算目标）、数据不出境与保密场景审计日志要求，与 SaaS 竞品形成部署模式的决定性错位。

### 7. 商业模式

- **收入模型**: 单一轨——私有化部署授权（一次性授权 + 年度维保）；安全保密场景 SaaS 不适用，**无 SaaS 形态**
- **定价策略**: 对标商业舆情平台（$10k–50k/年）的 1/10–1/5 定价区间切入，显著高于开源免费但远低于 Meltwater/Talkwalker；具体档位见第 23 节（全部为估算）
- **目标客户**: 国家安全机关（舆情分析相关部门）、国际关系/国际政治/国家安全研究机构（高校、研究院、涉外智库），全部为私有化授权交付

### 9. 执行摘要

全球媒体情报与消费者洞察市场由 Meltwater、Brandwatch、Talkwalker 等高价 SaaS 主导（$10k–50k/年），免费方案（GDELT、Media Cloud）则要求编程能力，国内政务舆情厂商（蚁坊、清博等）缺乏全球媒体覆盖与议程溯源能力——在国家安全与国际关系研究场景中，存在巨大的"议程设置行为识别 + 零编程可用 + 离线内网私有化部署"真空。AgendaScope 观澜以议程溯源与议程设置事件识别（US-06，P0 核心）+ 议程设置理论三层分析引擎 + 逐国 ≥70% 主流媒体覆盖口径 + 本地化部署 LLM（D-006）+ 完全离线内网部署切入该真空，MVP 覆盖 G20 及全球南方约 30 国，实时性硬指标为 P95 ≤ 30 分钟、红线 ≤ 2 小时。预期 6 个月达到 500 WAS/周、12 个月 2000 WAS/周（估算）。本次申请资源：MVP 期 1 名产品 + 2 名工程 + 0.5 名 NLP 顾问，6 个月交付（估算）。

### 11. 时机

为什么是 2026 年：

1. **技术成熟**: 跨语言 sentence-transformers（18.9k★）+ BERTopic（7.8k★，含在线/增量模式）+ trafilatura（6.3k★，正文抽取基准 F1 93.62）等开源组件全部活跃可用；开源大模型（如 Qwen 系列）已可在单卡 24GB 显存 GPU 或 CPU 量化环境下本地推理，议题分类/命名/归并/首发表述判定等 NLP 环节可直接交给 LLM，工程复杂度大幅下降。三年前搭这套管线需要一个 NLP 团队，今天是一个工程师的工作量（来源：调研报告 2）。
2. **免费数据基础设施就位**: GDELT 每 15 分钟更新、100+ 语言、65 种语言实时机器翻译且完全免费（来源：[GDELT 官网](https://www.gdeltproject.org/)）；RSSHub（45.4k★）可为无 RSS 的媒体补源。全球媒体监控的边际数据成本已趋近于零。
3. **学术范式转向**: 2025 年 *Communication and Change* 出版"AI 时代重访议程设置"特刊（来源：[Springer 特刊导言](https://link.springer.com/article/10.1007/s44382-025-00016-x)），计算议程设置研究进入高峰期，但研究者普遍缺乏工程能力——方法论需求与工具供给的剪刀差正在扩大。
4. **安全需求上升**: 国际舆论场的议程设置博弈持续升温，"某国率先提出涉华议题 → 多国媒体跟随"的模式反复出现（典型如"新疆棉"），国家安全机关与国际关系研究机构对"第一时间识别议程设置行为并固定证据链"的需求成为刚需，而现有工具无一可用。
5. **竞品空档**: 商业平台向社媒与消费者智能集中（Brandwatch 83 种语言但以社媒为主）且为纯 SaaS，国内政务舆情厂商海外覆盖弱，无人把"议程设置理论 + 议程溯源"做成可私有化部署的产品；开源舆情项目集中在中文热搜。窗口期存在但会关闭。

## 第三部分：市场分析

### 15. 市场概况

#### 15.1 市场定义

观澜所处的市场定义为"**全球主流媒体议程监控与议程设置行为识别**"，是媒体情报（Media Intelligence）大市场中"以传统媒体/新闻媒体为对象、以显著性与议程结构为度量、以国家安全舆情研判与国际关系研究为用途"的细分。边界：不做社交媒体全量监控与公众情绪分析（该领域由 Brandwatch/Talkwalker/清博等占据），不做金融合规级新闻数据库（Factiva/Aylien 领域），不做国内舆情处置（蚁坊/识微领域）。

#### 15.2 市场规模与增长

| 指标 | 数据 | 来源 |
|------|------|------|
| 当前市场规模 | 全球媒体情报/社媒聆听约 $50–80 亿/年；其中传统媒体议程分析细分约 $5–10 亿/年（估算） | 由竞品公开收入与第三方采购价格反推（来源：[CheckThat Brandwatch 定价](https://checkthat.ai/brands/brandwatch/pricing)） |
| 年增长率 (CAGR) | 约 8–12%（估算） | 行业普遍预期，无权威公开数字，标注估算 |
| 3 年后预测规模 | 细分市场约 $7–14 亿/年（估算） | 按上述 CAGR 外推 |

#### 15.3 市场趋势

1. **从社媒聆听回归新闻媒体** — 社媒平台 API 持续收紧、数据成本上升，研究与安全研判方重新重视可稳定获取的新闻媒体数据；GDELT/Media Cloud 的使用量与引用量持续增长（Media Cloud 架构论文 arXiv:2104.03702 被引 114 次）。
2. **私有化与数据合规成为采购硬条件** — GDPR、数据跨境与新闻版权压力下，机构倾向自有服务器部署；对国家安全场景而言，数据不出域、离线内网、等保合规是不可谈判的前置条件，纯 SaaS 竞品无法进入该预算。
3. **计算传播方法工业化** — BERTopic、Granger 因果、QAP/MRQAP 从论文方法变为工程组件（BERTopic 7.8k★ 活跃维护），开源大模型可本地部署承担议题分类与命名，"理论驱动的监控产品"首次具备可行技术栈。
4. **全球南方舆情监测需求上升** — 国家安全与国际关系研究对印度、巴西、尼日利亚、印尼等非英语主流经济体的媒体议程监测需求增长，而现有商业产品的覆盖与语言支持以欧美为主。

### 16. 目标市场细分

| 细分 | 规模 | 增长率 | 竞争强度 | 吸引力 |
|------|------|--------|---------|--------|
| 国家安全机关（国际舆情分析部门） | 各级相关单位（规模不公开，估算） | 高 | 低（无议程溯源竞品） | ★★★ |
| 国际关系/国际政治/国家安全研究机构（高校、研究院） | 全国数百个相关院系、研究院与课题组（估算） | 中 | 低（无理论化竞品） | ★★★ |
| 涉外智库（国际政治研究方向） | 数百至上千家（估算） | 高 | 中（国内舆情厂商出海覆盖弱） | ★★☆ |

**初始目标**: 国家安全机关 + 国际关系/国家安全研究机构。原因：①与产品差异化（议程溯源与议程设置行为识别）匹配度最高、付费理由最直接；②私有化与离线内网部署正是该客群的硬性采购条件，SaaS 竞品被天然排除；③陈国栋（国安机关分析师）、李思远（高校国际关系与国家安全学研究员）两个 P0 画像均在此细分，种子用户获取成本最低；④机构案例与学术引用可形成口碑飞轮反哺智库等扩展细分。

### 20. 护城河

1. **议程溯源与议程设置理论分析引擎**: 首发源判定、跟随国序列与时滞测量、传播链路图与议程设置事件自动判定，加上第一层客体显著性、第二层属性议程设置（实质+情感属性）、第三层网络议程设置（NAS）的完整计算测量链（时滞互相关 + Granger 因果 + QAP/MRQAP + intermedia agenda setting）。商业竞品没有动机为安全与研究细分投入该研发，开源项目没有理论能力与产品化能力同时具备的团队；复制需要"传播学方法论 × NLP 工程"的复合知识，属于人才护城河。
2. **70% 覆盖率口径**: 逐国"维基百科 + ABYZ + Media Cloud Directory + awesome-rss-feeds + Similarweb 交集 + 置信度标注"的媒体清单是持续运营出来的数据资产（各商业平台均不公开逐国覆盖统计，精确覆盖率只能自行估算——来源：调研报告 1 §2.4）。口径本身成为被引用标准后，形成品牌护城河。
3. **安全合规交付能力**: 完全离线内网部署（本地化 LLM 推理 + 离线地图 + 无外部依赖安装包）、对标等保 2.0 三级（估算目标）、数据不出境与保密审计日志——这套合规工程能力把 SaaS 竞品与绝大多数国内舆情厂商挡在门外，且随测评资质与标杆案例积累持续加深。
4. **零编程可用性**: "核心任务 ≤3 步、首次配置 ≤10 分钟、Docker Compose 一键部署"的体验标准，把学术级分析的门槛降到零，直接锁定被 GDELT/Media Cloud 拒之门外的业务专家用户群；体验护城河随模板库与用户口碑复利。

### 21. 竞争定位声明

> "Unlike Meltwater / Talkwalker（高价 SaaS 舆情平台）、GDELT / Media Cloud（免费但需要编程的数据源）与蚁坊/清博（国内舆情厂商），AgendaScope 观澜把议程设置行为识别——首发源判定、跟随国序列、时滞测量与传播链路证据链——连同议程设置理论三层分析引擎，做成完全离线内网部署、零代码可用的产品，这意味着国家安全机关与国际关系研究机构的业务专家都能在 2 小时延迟红线内，亲眼看到谁在为世界设置议程。"

### 31. 决策依据

- **为什么采集与分析先于预警**: 延迟红线与覆盖率口径是产品全部价值的地基，议程溯源、预警与深度分析（属性/NAS/对比）是其上的放大器；没有达标的采集分析，溯源与预警只会放大噪声。
- **为什么议程溯源（US-06）是 P0 核心而非 P1 增强**: "识别这是一次议程设置"是新产品定义下用户的核心价值与产品的差异化所在，也是竞品（无论国际 SaaS 还是国内政务舆情厂商）均未提供的能力；降级为增强项等于放弃品类定义权。
- **为什么自我纠错（US-16）是 P0 而非增强项**: 首发源误判与议题误并/误拆不是边缘情况而是概率必然——聚类与 LLM 判定在实时流上必然出错，一次误判若不能随证据自动修正，"新疆棉"类关键案例的证据链就会建立在错误首发源上，直接摧毁 US-06 的可信度与产品差异化根基；而"今天只有零星报道、明天才成形"的滞后若靠人工补录，实时监测价值归零、且人力不可扩展。因此次日自动归并、增量重估判定修正与 revision_log 全程留痕必须与首次识别同版本交付（借鉴 IntelligenceIntegrationSystem 主题合并与回声消除设计并超越，详见决策 D-007）。
- **为什么私有化是唯一交付形态**: 安全保密场景 SaaS 不适用——数据不出域、离线内网、等保合规是国家安全机关与涉密研究机构的不可谈判前置条件；明确不做 SaaS 形态，全部交付与定价围绕私有化授权 + 年度维保展开。
- **被降级的事项**: 公众议程直接测量（V2.0）、社交媒体全量监控（明确 Out of Scope）、40+ 国扩展（V1.1，按需驱动而非一次性铺开）——原因是 NLP 质量与覆盖率置信度需在 30 国范围内先验证，避免广度稀释深度。
